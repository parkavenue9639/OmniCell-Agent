# 探索性分析

先把用户目标收敛为可执行、可验收的科学问题，再判断是否能由已注册的标准 Tool 或它们的组合完成。质量控制、归一化、聚类、marker 提取、PCA 绘图和细胞注释都不属于探索性分析的默认适用范围；不能因为用户说“分析一下”就恢复为固定全流程。

只有目标需要非标统计、特殊图表或当前公共 Tool 尚未覆盖的方法时，才调用 `run_exploratory_analysis`。调用前明确目标、权威输入、必要假设、期望 artifact 和验收标准；目标仍有多种实质不同解释且会改变科学结论时，先向用户澄清。

该能力在受控环境中把目标拆成最少必要步骤，优先复用已注册的确定性 Recipe，仅在 Recipe 不覆盖当前步骤时生成有界代码。代码只处理本次 invocation 的权威输入和输出目录，不依赖其他 Tool 调用遗留的 Python 状态，不下载替代数据，也不隐式执行计划外处理。

验收时明确列出实际执行步骤、参数或假设、生成 artifact、可复查结果、失败或降级步骤以及科学限制。不得把代码运行成功、图像可读或文件生成等同于科学结论已经可靠。
